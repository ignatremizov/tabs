Marking & Paste (Developer Notes)

Marking is the TreeView's batch-selection system. It lets users select a set of nodes and move them as a group (including their descendants). The key goals are: fast batch moves, stable ordering, and no recursion hazards when moving into marked ancestors.

Data model

  • Node.marked — explicit mark flag (boolean).
  • Tree.markedNodes — array of explicitly marked node IDs.
  • Node.markedBy() — returns the nearest marked ancestor.

Marked state is serialized with normal tree persistence because marked lives in Tree.dictable. However, it is intentionally stripped from export backups via Tree.serializeNodes(forBackup=true), so backups do not restore marking state.

Rules for marking

  • Root and window nodes cannot be marked.
  • If an ancestor is already marked, a mark request is ignored.
  • Marking a node unmarks all of its descendants.
  • Moving a marked node under a marked parent unmarks it to avoid nested marks.

These rules keep the set of marked nodes flat and prevent infinite recursion when pasting into marked subtrees.

UI behavior

  • view/nodeview.js adds a .marked class to rows when node.marked is true.
  • The marked count widget (#marked-count) shows how many nodes are explicitly marked. It appends + if any marked node has children (meaning more nodes will move by association).
  • Clicking the marked count triggers action_pasteMarked().

Default shortcuts

  • M: toggle mark on cursor node.
  • Shift+M: unmark all.
  • P: paste marked after cursor.
  • Shift+P: paste marked before cursor.

These bindings are configurable in Options and live in common/keybindings.js.

Paste behavior

Marked nodes are moved as a block in pre-order tree order. This makes paste stable and deterministic even if the user marked items in a different order. The block is moved (not copied), and marked state remains unless a mark rule clears it.

  • action_pasteMarked() moves the block after the cursor, or into the cursor as the first child if the cursor is expanded.
  • action_pasteMarkedBefore() moves the block before the cursor, at the same parent level.
  • If the cursor is root, both paste actions insert at the top of root.
  • If the cursor is inside a marked ancestor, the destination is forced above that marked ancestor to avoid recursion.

Persistence and messaging

  • Node.setMarked() emits tree_nodeChanged with type: 'setMarked' on user action.
  • Tree.onMessage() applies mark changes to keep views in sync.
  • NodeStore.setMarked() persists mark changes to IndexedDB.
