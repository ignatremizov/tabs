Node ID Flow (Developer Notes)

This document explains how node IDs are generated, distributed, and stored. IDs are currently treated as opaque strings by the app, but their structure enables future tooling like ordering by creation time or ID validation.

ID format

IDs are created by IdGenerator in common/id-generator.js. The format is date-seq-name:

  • date: base32 timestamp (ms resolution)
  • seq: base32 sequence counter (optional if zero)
  • name: client ID (sanitized hostname or user ID)

Base32 encoding uses Crockford-style digits in common/base32.js. Decode is available for future use, but the app currently treats IDs as opaque.

When IdGenerator.newId() is called without a timestamp, it waits for the next millisecond if the per-ms sequence counter overflows. If a timestamp is passed explicitly, overflow throws to preserve deterministic IDs.

Where IDs are generated

IDs are generated only in the background service worker:

  • bkgd/bkgd.js initializes IdGenerator and exposes bkgd_newNodeId for the UI to request new IDs.
  • After the tree loads, IdGenerator.cache is set to TreeStore.nodes so new IDs skip existing ones on restart.
  • bkgd/nodestore.js uses IdGenerator directly when background code creates nodes.

UI flow (NodeView)

  1. The view requests an ID via emit('bkgd_newNodeId') in view/nodeview.js.
  2. The background replies with IdGenerator.newId().
  3. The view uses that ID when creating a new node in the tree.

Background flow (NodeStore)

  1. Background code creates nodes through NodeStore.addChild() in bkgd/nodestore.js.
  2. If no ID is supplied, NodeStore.newNodeId() allocates one via IdGenerator.
  3. The node is saved into IndexedDB (see bkgd/idb.js).

Where IDs are used

  • Primary key for nodes in memory (Tree.nodes cache).
  • IndexedDB key for stored nodes (object store Nodes).
  • Message payload references (e.g., move/delete events).
  • DOM node identifiers in the view (node${id}).

Potential future uses

  • Sync/merge tooling that compares creation times.
  • Debug tools that search or jump to a node by ID.
  • Import/migration workflows that validate or normalize IDs.
