IndexedDB Storage (Developer Notes)

Tree data is persisted in IndexedDB so it survives browser restarts. The background service worker owns all database access; UI views fetch tree data through emit('bkgd_getTree').

Database layout

Database name: TKTSTO. Object stores:

  • Nodes — node records keyed by node ID.
  • Snapshots — full tree snapshots keyed by name.
  • Transactions — reserved for future log/undo support.
  • Ops — durable background ops (intent queue + reconcile).

Ops queue storage

The Ops store persists resumable background operations so the service worker can recover after termination. Each record is keyed by opId and includes a state (pending/running/failed/done), timestamps, and an optional cursor for replay checkpoints.

Ops record fields: opId, state, type, name, source, createdAt, updatedAt, retryCount, lastError, payload, cursor.

Retry behavior: failed ops are re-queued after a backoff delay, while stale running ops (left running after a service worker crash) are re-queued after a longer threshold. Both are bounded by maxRetries.

Maintenance: the background prunes old done ops on a periodic timer to keep the queue size manageable and also removes ops which reference missing node IDs. For manual cleanup, the background accepts bkgd_pruneOps (remove old done ops and optionally dangling ops) and bkgd_clearOps (clear all ops) messages.

Reconcile scheduling: the background registers a periodicReconcile alarm and runs a reconcile pass on startup. Dirty hints are tracked with reconcileDirtyAt and reconcileDirtySource for future scheduling/diagnostics.

See bkgd/ops.js for queue behavior and bkgd/reconcile.js for the periodic reconcile pass that keeps tree state aligned with browser state.

How nodes are stored

Each node is serialized via Node.toDict() and stored by ID. The list of persisted fields is defined by Tree.dictable. Add new persistent fields by updating both Node defaults and Tree.dictable.

Key persisted fields

  • id, type, parent, nodes[]
  • label, note, title, url
  • windowId, tabId, loaded, wasLoaded
  • geometry, windowState, incognito
  • expanded, marked, checkbox
  • ctime, mtime, atime

Persistence flow

  1. Tree nodes live in memory in TreeStore (background).
  2. Mutations in the background use NodeStore, which calls db.saveNode() after changes.
  3. UI changes emit events to the background; background updates nodes and persists them.
  4. On startup, TreeStore.loadTreeFromDB() loads nodes and rebuilds the tree from serialized data.

Backups vs IndexedDB

Backups are JSON exports generated from the in-memory tree (see Tree.downloadBackupNow()). These are separate from the IndexedDB storage and are meant for user-controlled archival or migration.

  • bkgd/nodestore.js — write-through persistence on node edits.
