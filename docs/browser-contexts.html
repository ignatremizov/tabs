Firefox Containers and Native Tab Groups

Containers: keep the correct account

Open a tab in a container using Firefox's normal container controls. The outline displays a compact colored container icon next to the page title, without repeating the container name on every row. Hover over the icon to see the container's name and cookie-store identifier, or use the details panel. The full identity is also available to screen readers. Container renames and appearance changes update both live and saved rows. Missing containers retain a visible warning as well as an explanatory tooltip.

Unloading and reopening a saved tab uses its exact original cookie store, including when it is the first tab of a restored window. Two copies of the same URL in different containers remain separate. The extension never opens the URL in the default container first and then moves it.

Existing history: live tabs are annotated when this version attaches to them. Older closed entries that never recorded a container do not contain enough information to reconstruct their original account context; they retain the legacy default/inherited-window restoration behavior. Open those URLs in the intended container manually when the choice of account matters. Imported entries that name a container ID but omit its profile scope are blocked.

This preserves the choice of session, not a copy of authentication. Cookie contents, passwords, and authentication tokens are not read or saved by this feature. Existing cookies remain in Firefox; a site can still expire your login. Restoring a tree backup does not restore deleted cookies.

A deleted, inaccessible, foreign-profile, or unscoped imported container blocks restoration with an explanation instead of silently using another account. The saved row remains intact. Creating a new container with the same name is not the same identity. Restore from the original Firefox profile, or explicitly open the URL in your chosen container using Firefox. Automatic cross-profile container remapping is not provided. Named containers cannot be restored into private windows or browsers without Firefox container support.

Native groups: a note for each group

Create a native tab group in Firefox. It appears as a colored note with the same name beneath the window. Renaming, moving, or collapsing the native group updates the outline. Editing the note's name or expanded state, or moving its members in the outline, updates the live native group.

Only actual members belong beneath a native group note. Member-to-member nesting is preserved, while unrelated live and saved descendants are promoted to the nearest compatible ancestor outside the group. For example, grouping A and C in the following branch produces:

Before                 After
Window                 Window
  A                      Research [native group]
    B                      A
      C                      C
                         B

Ordinary notes remain annotations, not implicit groups. Group names such as Pinned, -, and = are literal titles, not pin commands or dividers. Native groups are separate membership domains; they are not nested native groups.

Closing or unloading group members preserves their saved history beneath the group note. A note with no live binding displays (saved group). Loading a saved member reuses the corresponding live native group or creates one with the saved name, color, and collapsed state. Restored native session tabs reconnect to their existing notes instead of creating duplicate groups. Ephemeral browser group IDs are not exported in backups.

Permissions and compatibility

The Firefox build requests cookies and contextualIdentities for container identification and exact-store creation, and tabGroups for native group metadata. It does not add required website access. The container feature does not call cookie-reading APIs; the isolated developer integration test uses only synthetic loopback cookies.

Native group functionality is enabled only when the browser exposes the required group APIs. Ordinary tabs and outline notes continue to work without them. Firefox container identity is not interchangeable with a similarly named container in another profile or a Chrome profile.

API references: Mozilla: contextual identities, Mozilla: tabGroups, and Mozilla: moving a complete group.
