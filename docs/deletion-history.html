Recently deleted

The Deleted toolbar button opens local recovery history. Explicit outline deletions are recorded as actions containing the removed nodes, notes, page addresses, nesting, and browser-context references. A branch deletion is one action, not a separate entry for every child.

Recover without reopening pages

Choose Restore as saved. The recovered outline is saved-only: no pages, tabs, or windows open automatically. Existing container references and native-group information are retained, but obsolete live browser IDs are not reused. When you later open a saved page, the usual exact-container checks apply; a missing or incompatible container does not silently switch accounts.

Recovery uses the original parent and neighboring nodes when they still exist. Otherwise, it uses a surviving original native-group note or a clearly named Recovered deletions folder. A missing original group is recreated as a saved group note. Newer existing nodes are never overwritten.

Deleting a marked node offers to delete all marked branches in the current window/session scope, with one confirmation and one recovery entry. Descendants already covered by a selected ancestor are not counted twice.

This is deletion recovery, not universal Undo

Existing one-node deletion can promote children rather than delete a whole branch. In that case, history contains only the removed node. Restoring it does not move the surviving children back or overwrite their newer edits. Window unwrap/conversion operations likewise do not become a general edit journal.

Ordinary browser tab/window closes, automatic empty-window cleanup, reconciliation, title updates, and favicon changes do not fill this history. Use the browser's own recently closed controls or the existing saved outline for those cases. Undo for edits and moves is a separate future feature.

Retention and permanent removal

The defaults are 30 days, 200 deletion actions, and 32 MiB of recovery data. The first limit reached removes the oldest entries. You can change the bounds under Retention settings. Reducing a limit requires confirmation and may remove entries immediately. Expired data is pruned at startup, daily, and when history is accessed or changed.

An action too large for the configured budget is rejected before the outline or browser tabs are changed. Increase the limit, export a separate backup, or delete smaller branches instead. Small consumed-action receipts are retained separately with bounded size/count/age to prevent repeated restores from duplicating data; they do not retain the deleted branch payload.

Delete permanently removes a selected entry from local recovery history after confirmation. It does not erase exported backups or a branch that has already been restored. Normal outline backups do not include Recently deleted. Keep a separate backup for disk/profile loss.

Private windows and failures

A selection containing private-window data requires an additional explicit permanent-deletion confirmation. The entire selection is then removed without a recoverable history copy. No private URLs, labels, or notes are retained in the small duplicate-request receipt. Delete non-private branches separately when you want to retain their recovery data.

History and the tree deletion are committed in one database transaction. A failed write leaves the existing outline and open tabs intact. Closing the selected browser tabs happens only after that commit. If the browser refuses a close or group change, history is still available and reconciliation repairs the surviving browser bindings.

Selections changed in another view while you were confirming are rejected; review the updated outline before deleting. During an in-progress browser restore, wait for its tabs to settle and try again.

Storage version

This feature adds two stores through an IndexedDB version 3 migration. The existing node records are not rewritten by migration. Earlier schema-2 Ops records are also preserved, without replaying their old browser operations. Older extension builds that only understand database version 1 cannot open a profile after it has been upgraded. Keep a JSON backup before upgrading, and use a compatible newer build rather than downgrading that profile in place.
